# KSA 2026.9.7 ShaderExtensions Compatibility Fix Plan

## Findings

- The supported baseline is installed KSA `2026.9.7.5402`; no legacy compatibility work or validation is required.
- `KSA.Program.Main` constructs `Program`, calls `App.Run()`, and disposes `Program` from a `finally` block.
- ShaderExtensions prefixes `Program.Main` only to call `AssetEx.Init()`. `Main_Patch2` names Harmony's generated wrapper; it does not prove the prefix failed. If `AssetEx.Init()` threw, `Program` would not exist and `Program.Dispose()` would not be in the stack.
- Installed StarMap `0.4.6` confirms the current two-stage startup:
  - `GameSurveyer.TryLoadCoreAndGame()` calls `StarMapCore.Init()` before `GameSurveyer.RunGame()` invokes KSA.
  - `StarMapCore.Init()` calls `ModLoader.Init()`. `RuntimeMod.InitializeMod()` invokes each `[StarMapBeforeMain]` method while loading mods.
  - ShaderExtensions installs Harmony patches from `Setup()` during StarMap initialization. Its `Program.Main` prefix runs after StarMap initialization completes, but before KSA constructs `Program` or loads content.
  - `[StarMapAllModsLoaded]` runs later from `ModLibraryPatches.AfterLoad`, after KSA's mod-library load, and may be too late for XML serializer overrides.
- The `Program.Main` prefix should remain. Removing it changes working serializer-registration timing without addressing the crash.
- `ConstraintSim.UnlockShapes()` fails during `Program.Dispose()` because ground-clutter collider data is disposed while a vehicle update owns the shapes registry. Since disposal runs in `Program.Main`'s `finally`, this can replace the exception that originally escaped `App.Run()`.
- The log reaches `Application Initialization Complete` and `Controlling 'Rocket'`, then exits within one second without retaining the original exception.
- The deployed ShaderExtensions `v1.0.0.95d319a-debug` transpiler uses fixed `RenderGame` locals and broad render-pass anchors. These are the primary known compatibility risk for KSA `2026.9.7.5402`.
- ShaderExtensions has no unified lifecycle hook that disposes all static GPU resources before KSA destroys the renderer and Vulkan device.

## Assumptions

- Only KSA `2026.9.7.5402` will be marked compatible.
- KSA's shapes-registry guard must not be bypassed and disposal exceptions must not be swallowed.
- Installed StarMap `0.4.6` is the supported loader contract.
- Test ShaderExtensions alone before MPFX. Disable unrelated mods initially because recent logs contain separate KSAGEffects/GEffectsLogic failures.

## Implementation Checklist

- [ ] Add a narrow diagnostic Harmony finalizer around `KSA.App.Run()` that logs and returns the original exception unchanged before `Program.Main` enters its disposal `finally`.
  - Include the KSA version and full exception details; do not suppress or replace the exception.
  - Success criterion: reproduction logs the original `App.Run()` exception before the secondary shapes-registry exception.

- [ ] Reproduce on KSA `2026.9.7.5402` with only StarMap, KittenExtensions, and ShaderExtensions enabled.
  - Exercise initialization, vehicle control, and the first rendered frames; repeat with MPFX after the minimal case is characterized.
  - Success criterion: determine whether ShaderExtensions alone reproduces the failure and capture the original exception.

- [ ] Trace the original exception to the responsible ShaderExtensions hook before choosing the production fix.
  - Check `Program_RenderGame_Prefix`, `Program_RenderGame_Transpile`, `ImGuiPreRender`, first-frame `ScheduleRendererRebuild()`, and `Program_RebuildRenderer_Postfix` against KSA's current frame and vehicle-update synchronization.
  - Determine whether the failure is managed, Vulkan validation, or native-device related.
  - Success criterion: the exception and a repeatable operation identify the fix target.

- [ ] Retain `Program_Main_Prefix` and document its verified StarMap timing in `ShaderExtensions/Patches.cs`.
  - Keep `AssetEx.Init()` after StarMap loads mod assemblies and before KSA constructs `Program` and deserializes content.
  - Make `AssetEx.Init()` idempotent if repeated KSA entry-point invocation is possible.
  - Success criterion: serializer timing is unchanged and initialization occurs exactly once.

- [ ] Refactor `Program_RenderGame_Transpile` for KSA `2026.9.7.5402`.
  - Match the ordered `RenderFinalComposite` → `RenderDrawData` → corresponding `EndRenderPass` sequence instead of the last method named `EndRenderPass`.
  - Capture typed command-buffer and frame-resource load instructions from the matched KSA sequence instead of emitting `Ldloc_1` and `Ldloc_0`.
  - Require each semantic anchor to resolve exactly once and fail with an actionable KSA-version message otherwise.
  - Success criterion: transformed IL has balanced render-pass boundaries and invokes each ShaderExtensions hook exactly once with correctly typed operands.

- [ ] Remove the unused `dynamicOffset` parameter from `GlobalPostShaderHandler.RenderNow`, unless tracing proves KSA's current shader-slot local must be propagated.
  - Success criterion: the injected call has no hard-coded compatibility placeholder and passes only consumed data.

- [ ] Implement the smallest production correction indicated by the captured original exception.
  - Confine the change to the failing initialization, render, or renderer-rebuild hook; do not patch KSA physics or `ConstraintSim.UnlockShapes()`.
  - Success criterion: the original exception no longer occurs under the same reproduction steps.

- [ ] Add one idempotent ShaderExtensions shutdown path while KSA's renderer and Vulkan device remain valid.
  - Dispose `PostProcessingHandler`, `GlobalPostShaderHandler`, `ImGuiRenderers`, and `SharedTimeBuffer` through the narrowest verified lifecycle callback.
  - Keep cleanup separate from KSA planet, clutter, and physics disposal.
  - Success criterion: normal shutdown has no double disposal, use-after-device-disposal, or shapes-registry access from ShaderExtensions.

- [ ] Add focused tests for KSA `2026.9.7.5402` patch selection and generated IL.
  - Assert that the `Program.Main` prefix remains installed and only adds the prefix call.
  - Assert that all `RenderGame` anchors resolve once, captured operands have expected types, and emitted stack behavior is valid.
  - Success criterion: tests pass against the installed KSA assembly and fail clearly if its layout changes.

- [ ] Add concise production diagnostics for startup, patch installation, first-frame rebuild, and shutdown.
  - Log KSA and ShaderExtensions versions and selected render anchors once.
  - Retain the `App.Run()` diagnostic if low-noise; otherwise remove it after verification and preserve equivalent logging at the corrected hook.
  - Success criterion: future failures identify the first failing operation without a full Harmony trace.

- [ ] Build the .NET 10 solution in Debug and Release.
  - Success criterion: both configurations compile against installed KSA `2026.9.7.5402` without new warnings caused by the fix.

- [ ] Validate KSA `2026.9.7.5402` with ShaderExtensions alone and with MPFX enabled.
  - Exercise startup, vehicle control, sustained rendering, renderer rebuild or resize, scene transition, and normal exit.
  - Confirm serializer extensions and shaders work, with no original `App.Run()` exception, shapes-registry exception, Vulkan validation error, or resource-lifetime error.
  - Success criterion: all scenarios pass on the version that will be marked compatible.

## Risks and Open Questions

- Until the original `App.Run()` exception is captured, the shapes-registry exception cannot safely be attributed to ShaderExtensions.
- `[StarMapAllModsLoaded]` is not equivalent to the current `Program.Main` prefix and may be too late for serializer customization.
- If the minimal configuration does not reproduce, narrow the scope through incremental mod enablement before changing ShaderExtensions.
- StarMap unload occurs after KSA `Program.Main` returns and may be too late for Vulkan cleanup, so the shutdown hook requires separate lifecycle verification.
